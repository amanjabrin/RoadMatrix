RoadMatrix Team GitHub Collaboration Guide

This guide explains how a 3-member development team can share and push the RoadMatrix codebase to GitHub, ensuring that everyone makes multiple small, incremental, descriptive commits to establish a realistic development contribution history.

💡 Feature-Based Ownership: Each developer owns specific features end-to-end, committing both the backend microservices and their corresponding React frontend screens.

1. Feature & Ownership Division

To divide contributions equally and create a rich commit history, commit scopes are assigned as follows:

Developer Assigned Scope (Backend + Frontend Pages) Key Responsibilities
Developer A Infrastructure & Fleet Feature
- backend/service-registry
- backend/config-server
- backend/api-gateway
- backend/fleet-service
- app/... (Vehicle Registry & Dashboard UI) 		Core infrastructure, routing, registry, database and UI for vehicle registry and tracking.
Developer B Auth, Drivers & Expense Features
- backend/auth-service
- backend/driver-service
- backend/expense-service
- app/... (Login, Drivers & Expenses UI) 		Security authentication, driver profiles/attendances, and operational fuel expenses logs (API + UI).
Developer C Company, Trips, Maintenance & Reports
- backend/company-service
- backend/trip-service
- backend/maintenance-service
- backend/notification-service
- backend/report-service
- app/... (Trip Dispatcher, Maintenance & Analytics UI) 		Multi-tenant company configuration, trip dispatch workflows, service logs schedules, notifications, and analytics dashboard reports (API + UI).

3. Step-by-Step GitHub Execution Plan

1 Initialize Git & Push Base Files (Developer A)

On the machine containing the complete codebase, Developer A initializes the project and pushes the shared configuration:

# Initialize repository
git init
git remote add origin https://github.com/your-username/RoadMatrix.git

# Add base configuration and guide files
git add .gitignore pom.xml .env COLLABORATION_GUIDE.md COLLABORATION_GUIDE.html
git commit -m "chore: initial project configuration and collaboration guide"
git branch -M main
git push -u origin main

2 Push Infrastructure & Fleet Changes (Developer A)

Developer A commits their assigned features in logical steps and pushes them:

# Commit Service Registry & Config Server
git add backend/service-registry/ backend/config-server/
git commit -m "feat(infra): add Eureka Service Registry and Config Server local setups"

# Commit API Gateway
git add backend/api-gateway/
git commit -m "feat(infra): add API Gateway with service routing and CORS headers"

# Commit Fleet Service Backend
git add backend/fleet-service/
git commit -m "feat(fleet): implement fleet-service backend vehicle JPA controllers and database seeder"

# Commit Frontend Layout and Vehicle Registry UI
git add app/src/components/ app/src/pages/VehicleRegistry.tsx app/src/pages/Dashboard.tsx app/package.json app/tsconfig.json app/vite.config.ts app/index.html app/postcss.config.js app/tailwind.config.js
git commit -m "feat(frontend): create base UI layout, navigation, and vehicle registry integration"

# Push all Developer A commits
git push origin main

3 Commit and Push Auth, Drivers & Expenses (Developer B)

Developer B clones the repo, copies their assigned folders (both backend services and React pages) into their local clone, and commits them in parts:

# Clone repository
git clone https://github.com/your-username/RoadMatrix.git
cd RoadMatrix

# Rebase to stay in sync
git pull origin main --rebase

# Commit Auth Backend & UI
git add backend/auth-service/ app/src/pages/Login.tsx app/src/pages/ForgotPassword.tsx app/src/pages/ResetPassword.tsx app/src/context/
git commit -m "feat(auth): implement auth-service JWT token utilities and login screen"

# Commit Driver Backend & UI
git add backend/driver-service/ app/src/pages/Drivers.tsx
git commit -m "feat(driver): implement driver-service profiles and frontend drivers registry"

# Commit Expense Backend & UI
git add backend/expense-service/ app/src/pages/Expenses.tsx app/src/lib/api.ts
git commit -m "feat(expense): implement expense-service fuel logs database and frontend Expenses screen"

# Push Developer B commits
git push origin main

4 Commit and Push Company, Trips, Maintenance & Reports (Developer C)

Developer C clones the repo, copies their assigned folders into their local clone, and commits them in groups:

# Clone repository
git clone https://github.com/your-username/RoadMatrix.git
cd RoadMatrix

# Rebase to stay in sync
git pull origin main --rebase

# Commit Company & Trip Workflow
git add backend/company-service/ backend/trip-service/ app/src/pages/TripDispatcher.tsx
git commit -m "feat(trip): implement trip-service dispatcher database and frontend Trip Dispatcher"

# Commit Maintenance Scheduler
git add backend/maintenance-service/ app/src/pages/Maintenance.tsx
git commit -m "feat(maintenance): add maintenance-service logs and frontend Maintenance log schedule"

# Commit Notification, Report & Analytics UI
git add backend/notification-service/ backend/report-service/ app/src/pages/Analytics.tsx app/src/pages/Settings.tsx
git commit -m "feat(analytics): add report-service analytics and frontend Analytics panel"

# Push all Developer C commits
git push origin main

4. Important Rules for Team Collaboration

⚠️ Never Commit Local Credentials: Ensure .env is never added to Git. Each developer must copy .env locally with their system's PostgreSQL username and password.

✔️ Rebase Before Pushing: To avoid merge commits and conflicts, always run git pull origin main --rebase before pushing any new commits.
